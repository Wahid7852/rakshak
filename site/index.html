case file · problem statement 1 · autonomous threat hunter for insider attacks

The quiet ones never look like an attack.

RAKSHAK is a central node that watches a whole fleet of employees at once, builds a behavioral baseline for each person from their own history, and scores new activity against it, not against an office-wide rule. No labeled attack data. No employee gets their own copy of the system.

what it does

One node, a fleet of baselines

Thin collector agents sit on each monitored machine and forward login, file-access, and data-transfer events to one central RAKSHAK node - not one RAKSHAK installed per employee. The node builds a behavioral baseline per employee from their own history, scores new events against it with an unsupervised anomaly engine, and surfaces alerts with a severity score and a plain-language reason.

The one rule the whole design answers to: no single anomalous event should ever reach high severity alone. Risk decays on a 3-day half-life; severity only escalates on sustained or corroborating signal.

why this approach

Insiders don't trip signatures

An insider isn't running exploit code a signature can match, and there's no labeled dataset of "insider attacks" the way there is for malware families or network intrusions. The same badge-in, file-open, and file-copy look identical whether someone's doing their job or staging an exit.

A flat threshold answers the wrong question: "more than N files an hour" either fires constantly for anyone whose job involves bulk access, or misses a quiet pattern that never crosses the global line. The only question that actually separates the two is whether this is unusual for this person, which is why the whole system is built around a baseline per employee, not a rule for the office.

who it's for

One screen, not a tool on every desk

A security team watching an organization's endpoints from one place, not an employee-facing tool, and not something installed with detection logic on every machine. One central node does the baselining, scoring, and alerting; thin collector agents on each monitored machine only forward events.

That split matters for who can actually run this: an org already collecting login, file-access, and transfer logs, without a dedicated data-science team on hand to build and retrain a supervised model, since the anomaly engine calibrates from the traffic it sees and never needs a labeled training set to start.

beyond the brief

Five things the brief didn't ask for

ADD. 1

Dual-timescale baseline

A fast and a slow baseline run side by side. Catches an employee drifting a little further each week, gradually enough to fool a single adaptive average.

ADD. 2

HR signal fusion

A resignation or PIP flag raises scrutiny, but only ever amplifies a real anomaly - proven with a dedicated control employee carrying the HR signal and nothing else.

ADD. 3

Plain-language narrative

Every alert reads as a paragraph, grounded in real computed reasons, not a bare score.

ADD. 4

Analyst feedback loop

Confirm or dismiss an alert and that specific signal's weight adjusts for that specific employee going forward.

ADD. 5

Blast radius & time-to-critical

How much sensitive activity moved in the trailing two weeks, and a projected days-to-critical at the current rate.

security

What's actually enforced, not claimed

Same discipline the detection engine gets, applied to the system carrying employee behavioral data. Every item below is a real control in the codebase, not a policy statement.

AUTH

Key on every route

Every endpoint except the two health checks requires an x-api-key header, over both HTTP and gRPC.

RATE

Per-key rate limits

Ingest and scan endpoints are capped (120/min on insider ingest by default), keyed by API key rather than raw IP so proxied clients don't throttle each other.

CRYPT

Encrypted quarantine

A confirmed-malicious file is encrypted at rest before it's stored; the original is only deleted after the encrypted copy round-trips clean.

SANDBOX

Isolated, read-only analysis

Static file analysis runs inside a namespace-isolated jail and never executes the sample; a missing sandbox degrades to a stricter fallback instead of failing open.

LOCAL

Nothing leaves the machine

Narrative generation and every scoring step run locally and compose from numbers already computed; no employee behavioral data goes to a cloud API.

SCAN

Gated on every push

Static analysis and secret-scanning block CI on real findings, dependencies are audited for known CVEs, and the crypto library is pinned past its own disclosed vulnerabilities.
