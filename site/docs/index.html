The insider-threat path

Not the malware/log cascade (that's a separate pipeline, documented in the repo's own docs/ARCHITECTURE.md) - this is specifically how a login/file-access/data-transfer/HR event becomes a scored alert, module by real module.

requirements

What you need

  • Python ≥3.11 - the only hard requirement for the backend and test suite.
  • bubblewrap (bwrap) - optional, for the sandboxed static-analysis step on the malware side only; falls back to a degraded rlimit-only mode with a logged warning if missing. Not needed for the insider-threat engine at all.
  • pip install -e ".[quantum]" - optional, only needed to run file_qsvc for real on the malware side.
  • pip install -e ".[dev]" - pytest, ruff, mypy, bandit, pip-audit, for running the test suite.

quickstart

Run it yourself

# generate simulated per-employee logs (a minority carry an injected insider pattern)
python samples/insider/generate_employee_logs.py --employees 12 --insiders 3

# central node
rakshak-http

# collector agent - tails the generated logs, forwards batches to the ingest endpoint
python scripts/agent/collector.py --source samples/insider/logs --server http://127.0.0.1:8080 --once

# severity-scored alert feed
curl -H "x-api-key: dev-key" "http://127.0.0.1:8080/v1/insider/alerts?min_severity=high"

# dashboard
open http://127.0.0.1:8080/insider/dashboard

security controls

What's enforced, and where

The exact files, not a policy page. Every control here runs in CI on every push.

  • backend/api/security/auth.py - x-api-key required on every route except /health and /v1/healthz
  • backend/api/security/rate_limit.py - per-endpoint limits keyed by API key (insider ingest defaults to 120/min, overridable via RAKSHAK_RATE_INSIDER_INGEST)
  • backend/engine/quarantine.py - Fernet-encrypted at rest, original only deleted after the encrypted copy round-trips; cryptography>=44.0.1, pinned past its own disclosed CVEs
  • backend/engine/sandbox/runner.py - static file analysis in a read-only, namespace-isolated jail, never executes the sample; degrades to a stricter fallback rather than failing open when the jail is unavailable
  • backend/engine/insider/narrative.py - template composition only, no LLM or cloud call, nothing about an employee's behavior leaves the machine
  • .github/workflows/ci.yml - bandit (SAST) and gitleaks (secrets) block the pipeline on real findings; pip-audit checks every dependency on every run
